# Frontend Specification Document: Handmade Accessories Store

Oct 12, 2026 · @anvi

## 1. Colour palette

The direction is warm and editorial: ivory and cream, muted blush, soft sage and warm brown. The hex codes below are proposals taken from the reference mood, not a brand-approved palette. The client may supply real brand colours, and if so this table is updated first. Product photography and fabric swatches carry most of the colour, so the interface colours stay quiet.

Define every colour once as a design token (a CSS variable mapped into the Tailwind theme). No component may use a raw hex value.

| Token | Hex | Used for |
| --- | --- | --- |
| `--color-bg` | `#FAF6EF` | Page background (ivory) |
| `--color-surface` | `#F3EBDD` | Cards, panels, drawer background (cream) |
| `--color-surface-alt` | `#EDE2D1` | Hover and selected backgrounds, section bands |
| `--color-border` | `#E3D8C9` | Hairline dividers and input borders |
| `--color-text` | `#4A3A33` | Body text and headings (warm brown) |
| `--color-text-muted` | `#7A655B` | Secondary text, captions |
| `--color-primary` | `#4A3A33` | Primary buttons, key actions |
| `--color-primary-text` | `#FAF6EF` | Text on primary buttons |
| `--color-blush` | `#E8C4C0` | Soft accents, highlights, badges |
| `--color-blush-deep` | `#D9A5A0` | Hover on blush, selected borders |
| `--color-sage` | `#9CAF98` | Secondary accent, availability and success tints |
| `--color-sage-deep` | `#6F8470` | Success text and icons |
| `--color-lavender` | `#B9A9D1` | Rare accent only (for example a single highlight on a product) |
| `--color-error` | `#B3463F` | Errors and destructive actions |
| `--color-warning` | `#B7883A` | Warnings such as a price change |
| `--color-focus` | `#4A3A33` | Keyboard focus ring (2px, with a 2px offset) |

**Rules:**

- Body text and interactive controls must meet WCAG AA contrast. Antigravity checks every text and background pair in this table and reports any that fail; the proposed hex is then adjusted, not the rule.
- Never use colour alone to show a state. Selected, error and unavailable states also use an icon, text or shape change.
- No neon colours and no gradients, except a subtle one behind a photograph if it improves text readability.

## 2. Typography

The direction is an elegant serif for headings, a clean sans for interface text and prices, and a handwritten script used only for small accents. The font names below are proposals; the client may prefer others. Fonts are loaded through the framework's built-in font loading, with a real fallback stack for each.

| Role | Proposed font | Fallback | Notes |
| --- | --- | --- | --- |
| Headings | Cormorant Garamond | Georgia, serif | Used at 24 px and above only, because the thin strokes are weak at small sizes |
| Body and interface | DM Sans | system sans-serif | Buttons, labels, forms, prices, navigation |
| Script accent | Caveat | cursive | Rare: a short phrase such as "small but useful". Never for buttons, prices or anything required to be read |

**Type scale** (mobile size, then desktop size):

| Style | Mobile | Desktop | Weight | Used for |
| --- | --- | --- | --- | --- |
| Display | 40 px / 1.1 | 64 px / 1.05 | Heading font, 500 | Homepage hero |
| H1 | 32 px / 1.15 | 48 px / 1.1 | Heading font, 500 | Page titles |
| H2 | 26 px / 1.2 | 36 px / 1.15 | Heading font, 500 | Section titles |
| H3 | 20 px / 1.3 | 24 px / 1.25 | Heading font, 600 | Product names, card titles |
| Body | 16 px / 1.6 | 16 px / 1.6 | Body font, 400 | Paragraphs |
| Body small | 14 px / 1.5 | 14 px / 1.5 | Body font, 400 | Captions, helper text |
| Label | 13 px / 1.4 | 13 px / 1.4 | Body font, 500, spaced capitals | Option group names, small headings |
| Button | 15 px / 1 | 15 px / 1 | Body font, 500 | Buttons |
| Price | 18 px / 1.2 | 20 px / 1.2 | Body font, 500 | Prices |

No text below 13 px, and no text smaller than 16 px inside form fields (so mobile browsers do not zoom in).

## 3. Spacing, layout and shape

Generous whitespace is part of the look. When in doubt, use more space, not more decoration.

| Rule | Value |
| --- | --- |
| Spacing scale (base 4 px) | 4, 8, 12, 16, 24, 32, 48, 64, 96, 128 px |
| Page container | Maximum width 1280 px, centred |
| Side padding | 16 px on mobile, 32 px on tablet, 48 px on desktop |
| Section spacing | 64 px on mobile, 96 to 128 px on desktop |
| Grid | 4 columns on mobile, 8 on tablet, 12 on desktop, 24 px gutters |
| Product grid | 2 columns on mobile, 3 on tablet, 4 on desktop |
| Breakpoints | Tailwind's default breakpoints |
| Corner radius, buttons and inputs | 4 px |
| Corner radius, cards, images and panels | 4 px, or none for photographs |
| Corner radius, swatches | Circle (fabric swatches may use a rounded square if texture photos suit it better) |
| Borders | 1 px hairlines in the border colour instead of heavy shadows |
| Shadows | Only for drawers, modals and menus: one soft, low-opacity shadow |
| Image ratios | Product cards 4:5, gallery main image 4:5 or 1:1 (to match the client's photography), thumbnails 1:1 |

**Layout rules:**

- Design mobile first. Every page must work at 360 px width without sideways scrolling.
- Photography is large and edge-aware: full-width bands and large images are preferred over many small cards.
- Avoid heavy rounded cards everywhere, glassmorphism, floating decorations and decorative animation.

## 4. Component styles

Every state listed here must exist: default, hover, focus, active, disabled, and loading where it applies. Hover effects must also have a keyboard focus equivalent.

| Component | Style |
| --- | --- |
| Primary button | Brown background, ivory text, 4 px radius, 48 px minimum height, 24 px horizontal padding. Hover: slightly lighter brown. Disabled: muted background with reduced contrast and a clear not-allowed cursor. Loading: spinner replaces or follows the label and the button cannot be clicked again. |
| Secondary button | Transparent background, 1 px brown border, brown text. Hover: cream background. |
| Text link | Brown text with an underline; hover thickens the underline. |
| Icon button | 44 by 44 px minimum touch area, Lucide icon, visible focus ring, accessible label. |
| Text input | 48 px height, 1 px border, ivory background, 16 px text, label always visible above the field (placeholders never replace labels). Focus: focus ring. Error: error colour border, an icon and a message beneath. |
| Select, radio, checkbox | Built from accessible, keyboard-operable elements, styled to match the palette. |
| Product card | Photograph at 4:5, name in H3, price below, no heavy border. Hover: a gentle image change (second photo fades in if one exists, otherwise a very slight zoom). Whole card is one link. |
| Cards and panels | Cream surface or hairline border; no heavy shadows. |
| Cart drawer | Slides from the right on desktop and as a full-height panel on mobile. Cream surface, shadow, focus kept inside while open, closes with Escape and a close button. |
| Modal | Centred, cream surface, focus trapped, closes with Escape and a close button, used sparingly. |
| Toast | Small message at the bottom on mobile and top right on desktop, auto-dismissing but readable by screen readers, with a close button. |
| Badge | Small blush or sage label (for example "New"), text never below 13 px. Only used for facts the API provides. |
| Skeleton | Cream blocks matching the final layout, with a very gentle pulse that stops under reduced motion. |
| Empty and error states | A short heading, one sentence of help and one clear action, in the brand's warm tone. |

## 5. Configurator specification

The configurator is the centrepiece. It is one generic component driven by the option groups the API returns for a product. No product-specific option list appears in frontend code.

**Option group display types** (the API names the type for each group):

| Type | Used for | Appearance | Selection |
| --- | --- | --- | --- |
| `swatch` | Fabric | Row or grid of round or square swatches with a texture image and the fabric name shown for the selected one | Single choice |
| `colour` | Zipper colour, button colour | Small colour dots with a text name for the selected one | Single choice |
| `chips` | Size, closure, strap type, clip or tie | Text chips; a size chip may show a short measurement the API provides | Single choice |
| `toggle` | Lining, bow, optional loop or handle | A switch with a label and any price change | On or off |

**Option states:** default, hover, focus, selected, unavailable (with a short reason), and loading while a new quote is fetched. Selected is shown by a border and a check icon, not by colour alone.

**Group rules:**

- Required groups are labelled as required. Optional groups are labelled as optional.
- A group is shown only if the API returned it for this product.
- Options marked unavailable are disabled, visibly different and explained.
- If the API provides a default option for a group, it is pre-selected. Otherwise nothing is pre-selected.

**Preview panel:**

- Shows the main product photograph prominently.
- If the API provides a preview image for the current selection, it replaces the photo with a short crossfade.
- If it does not, the product photo stays and a large swatch card showing the chosen fabric appears beside or below it. The frontend never fakes a recoloured product.
- Under reduced motion, images change without animation.

**Price display:**

- A price breakdown lists the base price and each option's price change, followed by the total. All numbers come from the API's price quote.
- While a quote is loading, the total shows a loading state and Add to cart is disabled.
- If the quote fails, show the error state from the Security and Access Document.
- Prices are shown in rupees, formatted in the Indian number style.

**Selection summary:** a compact list of the chosen options, always visible near the Add to cart button, with a clear indication of any required choices still missing.

**Add to cart** is disabled until every required group has a selection and the latest quote is valid. The cart stores the selected option IDs, so the configuration can be reopened and edited from the cart.

**Build Your Own** is a guided entry: the customer picks a product, then lands in the same configurator as the product page. There is no second configurator.

## 6. Motion, sound and accessibility

**Motion** should feel tactile and restrained. Animation never delays navigation, checkout or any action.

| Interaction | Motion | Limit |
| --- | --- | --- |
| Fabric swatch selection | A small scale or ring change on the swatch | Under 200 ms |
| Preview change | Crossfade between images | Under 300 ms |
| Cart drawer | Slide in and out | 250 to 300 ms |
| Add to cart feedback | A small check or count change on the button and cart icon | Under 600 ms |
| Hover | Gentle image or underline change | Under 200 ms |
| Page transition | A short fade only, and only if it does not slow navigation | Under 200 ms |
| Scroll reveals | A light fade and rise for editorial sections, once only | Under 400 ms |

- Use Framer Motion only where it adds meaning; simple hover effects use CSS.
- When the visitor's system asks for reduced motion, remove movement and keep only instant or very short opacity changes.
- Nothing animates continuously and no decorative floating elements are used.

**Sound** is optional and subtle.

- Off by default, and never plays on first page load.
- A clearly labelled sound control in the header turns it on and off. The choice is stored as a harmless preference in the browser.
- Sounds play only after a customer action (for example selecting a swatch or adding to cart) and only if the customer has turned sound on.
- Sounds are short and quiet, with file sizes small enough not to slow the site.
- Sound files must be licensed for use. The files and their licence source are recorded when added.

**Accessibility baseline:**

- Everything works with a keyboard, in a logical focus order, with a visible focus ring.
- Every image has meaningful alternative text from the API, or an empty one if decorative.
- Every form field has a visible label and an error message linked to it.
- Swatches and chips have text names available to screen readers, not only images or colours.
- Drawers and modals keep focus inside while open and return focus when closed.
- Status changes (item added, price updated, error) are announced to screen readers.
- Touch targets are at least 44 by 44 px.
- Contrast meets WCAG AA.

## 7. API and integration spec

This is a proposed contract, not an agreed one. Members B and C must review it and approve a final version in `/docs/api-contract.md`. Until then the frontend builds against a mock adapter that follows exactly this shape. If a task needs a field or endpoint not listed here, Antigravity stops and reports the gap. It does not invent one.

Paths are relative to the public API base URL. Method names and paths are proposals.

| Area | Method and path | Sends | Returns |
| --- | --- | --- | --- |
| Products | `GET /products` | Optional query: category, search text, fabric, price range, sort, page | A page of product summaries and paging details |
| Categories | `GET /categories` | None | List of categories |
| Product | `GET /products/{slug}` | None | Full product with images and option groups |
| Price quote | `POST /products/{id}/quote` | Selected option IDs | Validated selection with a price breakdown and total, or field errors |
| Cart | `GET /cart` | None | The current cart with server-calculated prices |
| Add to cart | `POST /cart/items` | Product ID, selected option IDs, quantity | The updated cart |
| Update cart item | `PATCH /cart/items/{id}` | New quantity and/or new selected option IDs | The updated cart |
| Remove cart item | `DELETE /cart/items/{id}` | None | The updated cart |
| Sign up | `POST /auth/signup` | Name, email, password (and phone if required) | The new user, or field errors |
| Log in | `POST /auth/login` | Email, password | The current user, or an error |
| Log out | `POST /auth/logout` | None | Confirmation |
| Current user | `GET /me` | None | The user, or a not-signed-in response |
| Forgot password | `POST /auth/forgot-password` | Email | A neutral confirmation, whether or not the account exists |
| Reset password | `POST /auth/reset-password` | Reset token, new password | Confirmation or an error |
| Addresses | `GET /addresses` | None | The customer's saved addresses |
| Add address | `POST /addresses` | Address fields | The saved address, or field errors |
| Edit address | `PATCH /addresses/{id}` | Changed fields | The updated address |
| Delete address | `DELETE /addresses/{id}` | None | Confirmation |
| Checkout | `POST /checkout` | Address ID (or new address) | The order, and the information needed to start payment |
| Order list | `GET /orders` | Optional paging | The customer's orders |
| Order detail | `GET /orders/{id}` | None | The order with items, address, order status and payment status |

**Integration notes:**

- **Payment gateway:** the gateway is not chosen yet. The frontend only needs, from `POST /checkout`, whatever is required to start the gateway's payment screen. After the customer returns, the frontend calls `GET /orders/{id}` and shows the status it returns. The gateway's own redirect or callback is never treated as proof of payment.
- **Pending payments:** while the status is pending, the screen checks the order status again at a sensible interval for a limited time, then offers a manual refresh.
- **Authentication:** how the session is carried (cookie or token) is decided by B and C. The API client is written so only one file changes.
- **Images:** all image URLs come from the API. The frontend does not construct image addresses itself.
- **Cart for guests:** depends on the open decision about guest add to cart.
- **Errors:** every endpoint uses the same error shape (see next section).

## 8. Response shapes

These are the fields the frontend expects, in plain terms. They become TypeScript types in `lib/types/`. Field names are proposals for B to confirm. Anything marked optional may be missing and the interface must cope.

**Product**

| Field | Meaning | Optional |
| --- | --- | --- |
| `id`, `slug`, `name` | Identity and display name | No |
| `description` | Text about the product | No |
| `category` | Category ID and name | No |
| `basePrice` | Starting price in rupees, as a number or string agreed with B | No |
| `images` | List of image URL, alt text and order | No (may be empty) |
| `optionGroups` | List of option groups for this product | No (may be empty) |

**Option group**

| Field | Meaning | Optional |
| --- | --- | --- |
| `id`, `label` | Identity and name, such as Fabric | No |
| `type` | One of `swatch`, `colour`, `chips`, `toggle` | No |
| `required` | Whether a choice is needed before add to cart | No |
| `options` | List of options | No |
| `defaultOptionId` | Pre-selected option | Yes |

**Option**

| Field | Meaning | Optional |
| --- | --- | --- |
| `id`, `label` | Identity and name | No |
| `priceDelta` | Price change when selected | No |
| `available` | Whether it can be chosen | No |
| `unavailableReason` | Short reason when not available | Yes |
| `swatchImageUrl` or `colourValue` | How to draw the swatch or dot | Yes |
| `previewImageUrl` | Image for the preview panel | Yes |
| `detail` | A short measurement or note, for example a size | Yes |

**Price quote**

| Field | Meaning |
| --- | --- |
| `valid` | Whether the selection is allowed |
| `lines` | Each line with a label and an amount (base price, each option change) |
| `total` | Final price for one item |
| `problems` | If invalid, which groups or options are the problem and why |

**Cart and cart item**

| Field | Meaning |
| --- | --- |
| Cart: `items`, `subtotal`, `total`, `notices` | The list, the amounts and any changes the customer should see |
| Item: `id`, `productId`, `productName`, `image` | What the item is |
| Item: `selectedOptions` | Each group and the chosen option, as labels and IDs |
| Item: `quantity`, `unitPrice`, `lineTotal` | Amounts calculated by the server |
| Item: `status` | For example available, price changed, or no longer available |

**Address**

| Field | Meaning |
| --- | --- |
| `id`, `recipientName`, `phone` | Identity and contact |
| `line1`, `line2` (optional), `city`, `state`, `pinCode` | Address details in the Indian format |
| `isDefault` | Whether this is the default address |

**Order**

| Field | Meaning |
| --- | --- |
| `id`, `orderNumber`, `createdAt` | Identity and date |
| `items` | Product name, chosen options as text, quantity and amounts as they were at purchase |
| `address` | The delivery address as it was at purchase |
| `totals` | Item total, any shipping or other charges, and final total |
| `status` | Order status from the agreed list in `/docs/status-glossary.md` |
| `paymentStatus` | Payment status from the same list (pending, paid, failed, cancelled) |

**Error**

| Field | Meaning |
| --- | --- |
| `code` | A short machine-readable reason |
| `message` | A customer-friendly sentence |
| `fieldErrors` | Optional map from a field name to its message |

## 9. Open decisions

- [ ] **Brand colours (client):** does the client have brand colours or a logo, or are the proposed hex codes approved?
- [ ] **Fonts (client and A):** are Cormorant Garamond, DM Sans and Caveat approved, or does the client prefer others?
- [ ] **Photography (client):** image ratios depend on the real photographs. Will the client supply them, and in what ratio?
- [ ] **API contract (B and C):** approve or amend sections 7 and 8, including field names and paths.
- [ ] **Price format (B):** are prices sent as whole rupees, paise or decimal strings?
- [ ] **Preview images (B and C):** will the backend supply a preview image per option, or will the swatch-card fallback be used for release 1?
- [ ] **Guest cart (team and client):** can guests add to cart?
- [ ] **Shipping and other charges (client and B):** are there delivery charges or taxes in the order total, and where do they appear?
- [ ] **Sound files (client and A):** which sounds, and from which licensed source?
- [ ] **Logo and brand name (client):** still undecided, so the interface uses a replaceable placeholder.
